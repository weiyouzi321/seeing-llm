KV Cache

kv_cache

把已算过的 K/V 存起来，避免重复计算

它在做什么，为什么需要

自回归生成时，第 t 步需要前 t-1 个 token 的 K/V —— 这些在之前的步骤里已经算过。缓存下来后，每步只需算新 token 的 Q/K/V，把单步复杂度从 O(t²) 降到 O(t)。代价是显存随序列线性增长，这也是 K3 削减 75% KV、V4.1 Flash 把每 token 压到 890 字节的动机。

真实数字感受一下：DeepSeek V4.1 Flash 把主 KV 压到 FP4，官方口径 890 字节 / token。按 1M 上下文算， 光 KV 就是 890 MB / 序列 —— 这还没算 batch。所以「削减 KV Cache」 从来不是优化题，而是长上下文能不能落地的生死题。

kv_cache · 教学精简版python
# 增量解码：只算新 token，其余直接复用
def step(q_new, k_new, v_new, k_cache, v_cache):
    K = torch.cat([k_cache, k_new], dim=-2)
    V = torch.cat([v_cache, v_new], dim=-2)
    out = sdpa(q_new, K, V)
    return out, K, V          # 新缓存回传给下一步

这是为讲清原理写的精简版，去掉了 dtype / layout / 融合算子等工程细节； 生产环境请直接用 PyTorch 原生实现（它走的是 fused kernel）。
