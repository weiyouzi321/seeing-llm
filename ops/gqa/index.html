分组查询注意力，Qwen3.8 用 64 Q / 4 KV 的极端配比

它在做什么，为什么需要

多个 Q 头共享同一组 K/V 头。MHA 是 1:1、MQA 是全部共享（N:1），GQA 取中间：把 Q 头分组，每组配一对 K/V。收益几乎全在 KV Cache —— Qwen3.8 的 64 Q / 4 KV 意味着缓存量直接降到 1/16，而质量损失很小。

多头注意力 · Q 头与 KV 头的配对

多头不会增加计算量，但会成倍放大 KV Cache —— 因为每个 Q 头都要配一份 K/V。GQA 的做法是让一组 Q 头共用一对 K/V： 质量几乎不掉，缓存直接按比例砍。

参考实现

grouped_query_attention · 教学精简版python
def gqa(q, k, v, n_groups):
    # q: [B, H, L, dh]；k/v: [B, G, L, dh]，G = H // n_groups
    B, H, L, dh = q.shape
    q = q.view(B, H // n_groups, n_groups, L, dh)
    k = k.unsqueeze(2).expand(-1, -1, n_groups, -1, -1)
    v = v.unsqueeze(2).expand(-1, -1, n_groups, -1, -1)
    o = sdpa(q, k, v)
    return o.reshape(B, H, L, dh)

这是为讲清原理写的精简版，去掉了 dtype / layout / 融合算子等工程细节； 生产环境请直接用 PyTorch 原生实现（它走的是 fused kernel）。
